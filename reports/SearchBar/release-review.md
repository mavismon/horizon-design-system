## SVG icon attributes (width="14" height="14")

`SearchBar.tsx` line 48 (search icon) and line 56 (clear icon) both carry `width="14" height="14" viewBox="0 0 14 14"` as attributes on the `<svg>`, not in the stylesheet.

**Does gate 2 cover them?** No, not as written. The gate's "how to answer" says "read every declaration in the component's stylesheet. List every literal hex or px value". These are markup attributes, they are unitless numbers (SVG user units, which render as CSS pixels), and the stylesheet has no `width` or `height` on `.hz-searchbar__icon`, so nothing in `SearchBar.css` hits the gate. The gate's one-line question ("Does every value reference a token? Any raw hex or px?") could be read more widely, to cover a 14px size set in the component's code. If so, they are a finding, and nothing covers it: `decisions.md` has no SearchBar ruling, and the Button ruling covers `Button.css` only. No icon size token exists (the spacing scale has 12 and 16px, not 14px; there are no size tokens), as the QA report also notes.

**Decision for this review:** I treated gate 2 as written (stylesheet only) and passed it, and I am reporting the attributes openly rather than ruling them out. This does not change the verdict, which is Blocked on check 5 either way. If a human intends gate 2 to reach markup attributes, a ruling is needed that names exactly: `width="14"` and `height="14"` on the search icon (`SearchBar.tsx:48`) and the clear icon (`SearchBar.tsx:56`), accepted because they are the Figma icon size and no icon size token exists, until the designer adds one. I did not write that ruling.
