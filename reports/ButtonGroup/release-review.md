## Findings outside the gates

1. **Props that are not Figma properties.** `labels` (`ButtonGroup.tsx:31`), `onItemClick` (`:40`), `value`, `defaultValue` and `onValueChange` (`:48, 50, 52`), plus passthrough div attributes including `aria-label`. They are marked in the source as not Figma properties and added so the component is usable. They are part of the public API once published (a 0.x breaking-change surface for `VERSIONING.md`). Owner: a human, to accept them as intended API or ask the designer to draw them.
2. **Text editing in Figma.** The Usage frame 193:59 contains no line about editing text from the group's properties, so this review could not confirm it there. The story header says Figma edits the texts inside the instances, which is why `labels` exists. If the designer means the group should expose its text as properties, that is a design decision, not a gate finding.
3. **Figma property-name casing.** The source maps Figma's `ShowThird` and `ShowFourth` (PascalCase, per the story header) to the camelCase booleans `showThird` and `showFourth`. `type` and `layout` match the cell names (`type=primary, layout=row`). Button's precedent (`94900ff`, "match Figma prop/value names exactly") argues for the Figma spelling; Breadcrumbs keeps `ShowItem2` verbatim in its intent. Owner: a human, to settle one convention. Not a gate finding.
4. **Stack needs a parent with a defined width.** `.hz-buttongroup--stack` sets `width: 100%` (`ButtonGroup.css:12`), so in an auto-width parent it collapses to zero; the stories use a 320px wrapper (QA report, limitations). Consumers need to know. Not in the intent file; there is no field for it.
5. **`Dropdown` does not exist.** The third `dont_use_when` points to a component that is not built. Figma's own text; the pointer is a dead end until Dropdown exists. Owner: designer / planning.
6. **No story sets `showThird` or `showFourth`.** The three-button rows and stacks, and the three- and four-segment groups, exist in the code and were tested by QA through the args channel, but have no story of their own and no Storybook control. Owner: engineer, if the team wants them visible in Storybook.
7. **Chip and segmented overlap in practice.** Chip's "switch between categories of the same content" (a navy `selected-strong` category row) and ButtonGroup's segmented ("switch a view between 2 to 4 options", navy selected segment) are close. Both intents separate them only by ButtonGroup's "multiple values at once: use Chip" line. Check 6 passes on the literal test; the designer may want a sentence in Chip's `dont_use_when` pointing exactly-one choices of 2 to 4 options to ButtonGroup. Owner: designer / `component-intent`.
8. **Computed spacing.** The segment padding is `calc(var(--spacing-md) / 2)` and `calc(var(--spacing-md) - var(--border-width-sm))`, which give 6px and 11px, because Figma's 10px/16px-with-border values do not match a spacing token (the QA report measured 10px/16px). The values follow the tokens, but if the designer adds exact spacing tokens, these should bind to them.
9. **Contrast as drawn.** With the built tokens: unselected segment text `#4d5361` on `#f9fafb` is about 7.2:1, and selected text `#f9fafb` on `#161925` is about 16.8:1; both pass. The unselected segment border `#d7dee7` on `#f9fafb` is about 1.3:1, below the 3:1 guideline for the boundary of a control. The QA report also records dark-theme unselected segment text at about 2.9:1; that was not re-measured here. Owner: the designer.
10. **Possible Figma slip: check icons on "Do not use".** In frame 193:59, the three "Do not use a button group" lines (`193:187`, `193:193`, `193:199`) use the same green check asset as the "Use a Button group" lines (the same image constant in the design context), while "Best Practice" uses an info icon. A cross would be expected on the don'ts. Read as a Figma slip, not a code issue. Owner: the designer.
11. **Pipeline colour drift.** QA recorded the buttons rendering with `--color-primary-default` `#2b5ad6` (Figma `#3b71f2`) and `--color-status-error` `#d02727` (Figma `#ea3d3d`), the same accepted drift as Button, Chip and Toggle.
12. **QA report date.** The copied QA report is headed "Staging QA pass — 2026-10-03", while this review is dated 2026-10-02. The file was copied unchanged as instructed.
