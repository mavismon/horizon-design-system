## G5: a published variant that is not built

The skill's wording for G5 is: "Every variant and state the Figma node publishes exists in the code and is rendered by at least one story." Figma node `140:66` publishes `tone=inverse` at both sizes. It is not in the code and not in a story. Read literally, that is a failure of G5.

What the skill allows instead: "Any failure is `Blocked`, unless `decisions.md` has a ruling that covers exactly that finding", and "never stretch a ruling past its stated boundary". The only ProgressBar ruling, quoted below, covers G2 for two px values. Its "Not ruled" line names the `inverse` tone explicitly: "The `inverse` tone, which is not built because Figma draws its track and fill the same colour: that needs the designer." The QA report records the user's decision to build only three tones, but a decision recorded in a QA report is not a ruling in `decisions.md`, and this agent cannot write one. The skill has no "warn" outcome for G5 (the only warning in the whole skill is check 2), and "Never treat ... a failed gate as a warning."

So under the skill's wording this **blocks**. It should not pass and it should not be downgraded to a warning. The reason is a real design bug (Figma's inverse cells draw a track and fill of the same colour, `#f9fafb`, so the bar would show no fill), and the owner of that is the designer. Two ways out, neither of which this agent can take: (a) the designer fixes the inverse cells and the engineer builds the tone, then re-review; or (b) a human adds a `decisions.md` ruling that says the unbuilt inverse tone passes G5 until the designer fixes it, stating what is not ruled, then re-review. Everything else in this report passes, so (b) would flip the verdict to `Cleared` with no other change.

## Ruling applied

G2 passes under `decisions.md`, "2026-10-02 · ProgressBar track heights with no token":

> **Ruling.** These literals in `src/components/ProgressBar/ProgressBar.css` are accepted, because they are what the Figma node specifies, until the designer adds matching size tokens:
>
> | Value | Property | Selector | Lines |
> |---|---|---|---|
> | `8px` | `height` (md track) | `.hz-progressbar__track` | 50 |
> | `6px` | `height` (sm track) | `.hz-progressbar--sm .hz-progressbar__track` | 60 |
>
> **For an agent that hits it.** Gate 2 passes for exactly these values on exactly these properties in `ProgressBar.css`. Quote this ruling in the report. When a size token for 8px or 6px appears, the ruling no longer covers that value: use the token.
>
> **Not ruled.** Any other literal value, including a `var()` fallback. These values in any other component. A change to this value: a different number needs a new ruling or a token. The primary fill, which uses `--color-primary-default` (`#2b5ad6`) and differs from the `#3b71f2` Figma shows: that is the user's choice to use the bound token, not a gate finding. The `font-weight` values 400 and 600, which are unitless numbers and need no ruling. The `inverse` tone, which is not built because Figma draws its track and fill the same colour: that needs the designer. Any state Figma does not draw.

**Staying inside the boundary.** Line 50 of `ProgressBar.css` at the reviewed SHA is exactly `  height: 8px;` inside `.hz-progressbar__track` (lines 45-57); line 60 is exactly `  height: 6px;` inside `.hz-progressbar--sm .hz-progressbar__track` (lines 59-61). Value, property, selector and line match the ruling. There is no other literal and no `var()` fallback. No size token for 8px or 6px exists in `build/css/tokens.css` (`--spacing-sm` is 8px and `--radius-sm` is 6px, but they are spacing and radius tokens, as the ruling says), so the ruling still applies. The ruling was appended to `origin/main`'s `decisions.md` verbatim; `git diff` against `origin/main` shows only the added ProgressBar section.

**Primary fill, not a finding.** The primary fill is `var(--color-primary-default)` (`ProgressBar.css:2`), which `build/css/tokens.css` renders as `#2b5ad6` (the token's own comment: a WCAG AA fix, blue/500 to blue/600) against `#3b71f2` in Figma. The ruling's "Not ruled" paragraph records this as the user's choice. It is not a literal and not a gate failure; reported for the record.
