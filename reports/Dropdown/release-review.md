## Findings outside the gates

1. **Props that are not Figma properties.** `options`, `value`, `defaultValue`, `onValueChange`, `open`, `defaultOpen`, `onOpenChange` and `name` (`Dropdown.tsx:12 to 28`), plus passthrough div attributes. The source and the QA report say they were added so the component is usable. They are public API once published (a 0.x breaking-change surface under `VERSIONING.md`). Owner: a human, to accept them as intended API or ask the designer to draw them.
2. **Menu shadow.** Figma draws `0 4 12 rgba(15,23,41,.08)`; the code uses `--elevation-md` (`0 4 8`, alpha .12). QA recorded it as not failed by decision. Owner: the designer, to bind the effect style or add a matching token.
3. **Unspecified states.** Figma draws no hover, pressed, error or keyboard-focus styling. The engineer added keyboard focus (focus-blue border and outline) and the active-option inset outline, and no hover. Owner: the designer.
4. **Menu is an overlay.** The menu is absolutely positioned 4px below the field (`Dropdown.css`, `.hz-dropdown__menu`), while Figma places it in flow, so opening does not push content. Consumers need a parent with room; the stories use a 240 x 240 wrapper. Not expressible in the intent file.
5. **Dead-end pointers in `dont_use_when`.** `Radiocard` is not built (`src/components/` holds Avatar, Breadcrumbs, Button, ButtonGroup, Checkbox, Chip, Dropdown, Image, Link, Logo, ProgressBar, Toggle). The wording "Buttongroup" differs from the exported name `ButtonGroup`. Figma's own text. Owner: designer / planning.
6. **Intent `use_when` mixes guidance with uses.** Entries 2 to 6 ("Use size md...", "Show the label above...", "Always show a value...", "Order options...", "Keep option text short...") are Figma "best practice"-style lines transposed into `use_when`, which `component-intent` permits when they read as one. Reported for the designer; not a gate finding.
7. **Astro Link empty.** `release-review` expects `Astro Link` before a review, but `Astro Link` is written by devops after a Cleared verdict (the circular docs gate noted in `release.md`). The review therefore had no production docs page to read first, and compared the source with Figma and the QA report instead. Owner: devops, after merge.
8. **Computed spacing.** Field and option padding come from `calc()` over `--spacing-md` and `--border-width-sm` because Figma's 9px/6px paddings are not in the spacing scale. If the designer adds exact spacing tokens, these should bind to them.
9. **QA limitations carried over.** Inter was not installed in the test browser, so text widths are unverified; dark mode, long-value truncation and the hidden `name` input were not tested.
10. **Pipeline colour drift.** Same accepted drift as Button, Chip and Toggle: `--color-primary-default` `#2b5ad6` against Figma `#3b71f2`; here it affects the selected-option fill only through `--color-primary-light`, which QA measured at `#eff3ff`.
11. **a11y line precision.** The `aria-activedescendant` claim is cited at line 168 (the option) while the attribute sits on the button at line 151. Check 3 asks that the cited line is in the implementing code, and it is; owner: `component-intent`, if the team wants exact lines.
