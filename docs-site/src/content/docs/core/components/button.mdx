## When to use it

- To trigger a primary action, such as submitting a form or confirming a choice.
- When the action is a single, clear next step the user should take.
- For calls-to-action that need visual emphasis — use the filled/primary style.
- For secondary or less prominent actions — use the outline style instead of a second filled button.
- To open a modal, drawer, or another view, when the action is not a navigation link.
- For destructive actions (e.g. delete, remove), paired with the error/danger state.
- Inside forms, toolbars, cards, and dialogs — wherever a discrete, tappable action is needed.

## When not to use it

- For navigation between pages or views — use a Link component instead.<br/>**Instead:** Link
- When more than one primary action competes for attention on the same screen — keep only one primary button per view.<br/>*The Figma page names no alternative.*
- As a label or static status indicator — use a Badge/Lozenge component instead.<br/>**Instead:** Badge/Lozenge
- For a toggleable on/off state — use a Toggle or Checkbox component instead.<br/>**Instead:** Toggle or Checkbox

## Best practice

From the Figma documentation page (usage node `51:1158`), as written. These items aren't carried into `Button.intent.json`, which has no field for them.

- Use clear, action-oriented labels (e.g. "Save changes", not "OK").
- Keep a single primary (filled) button per screen or section; make all other actions secondary/outline.
- Always design a hover and error/disabled state so users get feedback on interaction.
- Don't stack more than two buttons side by side without a clear visual hierarchy.
- Keep button labels to 1–3 words; avoid full sentences.
- Reserve the error/outline-error state for destructive or blocking actions only.
- Keep a minimum 40px tap target height for touch interfaces.
