## When to use it

- Above the page title on pages that sit inside a hierarchy, such as a listing ("Stays / Portugal / Lisbon / Alfama") or a back office settings page ("Team and roles / Roles / Permissions").
- To let the user go back up to any parent page in one click.
- Show 2 to 4 levels; hide unused levels with ShowItem2 and ShowItem3.

**Property names.** Item 3 (Figma node `163:158`) is copied from Figma as written, with Figma's spelling of the properties. The code spells them [`showItem2`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Breadcrumbs/Breadcrumbs.tsx#L9) and [`showItem3`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Breadcrumbs/Breadcrumbs.tsx#L10).

## When not to use it

- On top-level pages that have no parent: there's nothing to show.<br/>*The Figma page names no alternative.*
- To show the steps of a flow, such as checkout: use the Stepper component instead.<br/>**Instead:** Stepper
- As the main navigation between sections: use the Sidebar or Header component instead.<br/>**Instead:** Sidebar or Header

## Best practice

From the Figma documentation page (usage node `163:42`), as written. These items aren't carried into `Breadcrumbs.intent.json`, which has no field for them.

- Make every item except the current page a link to that page.
- Use the same page names as the page titles and navigation, so the trail is easy to recognise.
- Keep the current page as the last item, styled darker and not as a link.
- Don't wrap breadcrumbs onto two lines; shorten long names instead.
- Mark the trail up as navigation for assistive technology (a nav landmark with aria-label="Breadcrumb", and aria-current="page" on the last item).

**Where the built component differs.** Item 1 (Figma node `163:186`) is copied from Figma as written. Whether it holds depends on the consumer passing the ancestor hrefs, which the component makes optional. [`item1Href`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Breadcrumbs/Breadcrumbs.tsx#L11), [`item2Href`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Breadcrumbs/Breadcrumbs.tsx#L12), [`item3Href`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Breadcrumbs/Breadcrumbs.tsx#L13) are not Figma properties. `Breadcrumbs.tsx` declares them as optional props and sets `href={a.href}` on each ancestor `<a>` ([`Breadcrumbs.tsx:40`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Breadcrumbs/Breadcrumbs.tsx#L40)), so an ancestor that is given no href renders an anchor without one.

From the [QA report](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/reports/Breadcrumbs/qa-report.md), as written:

> item1Href, item2Href and item3Href are not Figma properties. They are optional props added by the engineer so that the ancestor links have destinations; with no href an ancestor renders an &lt;a&gt; that is not a real link.

From the [release review](https://github.com/mavismon/horizon-design-system/blob/7eb2ff874ba3bb46634456343667b51123728540/reports/Breadcrumbs/release-review.md), under "Other findings", as written:

> item1Href, item2Href and item3Href are not Figma properties. Figma's design context for 163:2 lists only className, current, item1, item2, item3, showItem2, showItem3. The three optional href props were added by the engineer so that ancestors have destinations (the QA report says so). They are optional, so with none set, an ancestor renders &lt;a className="hz-breadcrumbs__link"&gt; with no href, which is not a link: it is not focusable and is not announced as a link. Figma Best Practice 163:186 ("Make every item except the current page a link to that page") therefore depends on the consumer passing the hrefs: the component does not enforce it. The fourth a11y fact ("Each ancestor is a native &lt;a&gt;, so keyboard focus, the focus ring and activation are the browser's own") holds only when an href is passed. The stories pass "#" for all three, so every story shows links. Owner: engineer or designer, to decide whether the hrefs should be required, or documented, or whether Figma should gain a link property.

Breadcrumbs has no variant union type, so there are no variant values to explain: `Breadcrumbs.tsx` exports none, and [`showItem2`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Breadcrumbs/Breadcrumbs.tsx#L9) and [`showItem3`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Breadcrumbs/Breadcrumbs.tsx#L10) are `boolean` props (`variant_intent` is empty in `src/components/Breadcrumbs/Breadcrumbs.intent.json`). The Design tab shows the 4 combinations that Figma draws.

## Accessibility

- The trail is a native &lt;nav&gt; landmark labelled "Breadcrumb", containing an ordered list; the label can be overridden through the passthrough props. [`src/components/Breadcrumbs/Breadcrumbs.tsx:36`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Breadcrumbs/Breadcrumbs.tsx#L36)
- The current page is the last list item, a non-link &lt;span&gt; marked aria-current="page". [`src/components/Breadcrumbs/Breadcrumbs.tsx:49`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Breadcrumbs/Breadcrumbs.tsx#L49)
- The "/" separators are aria-hidden so assistive technology does not announce them. [`src/components/Breadcrumbs/Breadcrumbs.tsx:43`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Breadcrumbs/Breadcrumbs.tsx#L43)
- Each ancestor is a native &lt;a&gt;, so keyboard focus, the focus ring and activation are the browser's own; no focus style is overridden. [`src/components/Breadcrumbs/Breadcrumbs.tsx:40`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Breadcrumbs/Breadcrumbs.tsx#L40)

The release review says the last fact above, about the native `<a>`, holds only when an href is passed. See the note under Best practice.
