## When to use it

- Use type listing for something people can open or book: a stay, an experience, or a trip, with a photo, a title, one details line and the price.
- Turn on ShowTag for a status on the photo, such as "Confirmed", and ShowAction for a text action such as "View"; turn ShowRating off when there are no reviews yet.
- Use type stat in the back office for one key number, such as "Active admins 27", in a row of 3 to 5 tiles at the top of a page.

3 more lines in `use_when` in `src/components/Card/Card.intent.json` (items 4 to 6) are Figma's Best Practice lines, word for word. They are listed once, under "Best practice" below.

**Property names.** Item 2 (Figma node `239:57`) is copied from Figma as written, with Figma's spelling of the properties. The code spells them [`showTag`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Card/Card.tsx#L13) and [`showAction`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Card/Card.tsx#L20) and [`showRating`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Card/Card.tsx#L18).

## When not to use it

- For rows of data people compare or sort: use a Table.<br/>**Instead:** Table
- To choose one option in a form: use Radiocard.<br/>**Instead:** RadioCard
- For a stat that needs a chart or several numbers: use a content panel, not a stat tile.<br/>*The Figma page names no alternative.*

## Best practice

From the Figma documentation page (usage node `239:51`), as written. These items aren't carried into `Card.intent.json`, which has no field for them.

- Keep every card in a grid the same width and photo ratio, so titles and prices line up.
- One line each for title and details: they cut off with … rather than wrap.
- Make the whole listing card clickable, and keep the Action for a second, smaller step.

**Where the built component differs.** Item 3 (Figma node `239:68`) is copied from Figma as written. It is a design instruction, not something `Card` does: the card is a plain `<div>` ([`Card.tsx:60`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Card/Card.tsx#L60)) with no `role`, no `tabIndex`, no keyboard handling and no focus style (`Card.css` has no `:focus` rule), and Figma draws no focus state. Caller attributes are spread onto the `<div>`, so a consumer who adds `onClick` gets a mouse-only target. The `a11y` entries in `Card.intent.json` do not say so. This is a documentation gap for the designer and a human, not a feature.

From the [release review](https://github.com/mavismon/horizon-design-system/blob/6fc6fef5b0b0caa134c0c7e7347e61380348bfc7/reports/Card/release-review.md), under "Warnings (not blocking)", as written:

> The intent's best practice "Make the whole listing card clickable" has no support in the component: the container is a plain &lt;div&gt; with no role, keyboard handling or focus style (Figma draws no focus state). A consumer who adds onClick through the spread gets a mouse-only target, and the a11y entries do not say so. Named in the ruling's "Not ruled" line. Owner: doc-generator and a human.

## Accessibility

- The photo is Horizon's Image component, a native &lt;img&gt;, and imageAlt (default empty, so decorative) is passed to its alt. [`src/components/Card/Card.tsx:62`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Card/Card.tsx#L62)
- The card is a plain &lt;div&gt; with no role; title, details and price are &lt;p&gt; text, so they read in DOM order. Caller-supplied attributes (onClick, role, aria-*) are spread onto the container. [`src/components/Card/Card.tsx:60`](https://github.com/mavismon/horizon-design-system/blob/c1052106ef1cc81c8a4da5f07f6c686858758716/src/components/Card/Card.tsx#L60)

## Composition

`Card.intent.json` lists `Image` in `pairs_with`, but no story composes Card with it: `Card.stories.tsx` never imports or renders it, and every story renders Card alone. This page does not assert the pairing. What is true is composition inside the component: `Card.tsx` is built from [Image](/core/components/image/), as the registry's Composes column records and the Code tab shows.
