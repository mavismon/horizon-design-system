## When to use it

- To list records people scan, compare and act on in the back office, such as rate seasons, admins, invites or documents.
- Put the name of each record in the first column (primary), the status in a tag, and row actions such as "Edit" or "Resend · Revoke" in the last column.
- Turn on the checkbox column when people act on several rows at once, and show the selected rows in light blue.

## Where it goes

- Under header type=backoffice, to the right of the SideBar (the BackOfficePage story).

## When not to use it

- On the guest website or app for browsing stays: use Card type listing.<br/>**Instead:** Card
- For two or three facts about one thing, such as in a dialog: use detail rows.<br/>*The Figma page names no alternative.*
- Put long text or paragraphs in a cell: link to a detail page instead.<br/>*The Figma page names no alternative.*

## Best practice

From the Figma documentation page (usage node `251:353`), as written. These items aren't carried into `Table.intent.json`, which has no field for them.

- Keep column headers short and sentence case, and let people sort by the most useful column, usually the first.
- Use tag tones the same way everywhere: success for live or on file, error for expired or missing, neutral for past or draft.
- Show how many records there are in the footer, such as "Showing 1 to 5 of 7 seasons", and keep Previous and Next in the same place.

### Open items

They are open items, not waived.

**Open accessibility problem: the warning tag's text contrast is about 2:1.** The warning tone sets `--color-status-warning` text on `--color-status-warning-bg` ([`Table.css:138-141`](https://github.com/mavismon/horizon-design-system/blob/b9ffb76f7673fe33ddc04617d587557e93084f96/src/components/Table/Table.css#L138-L141)), 11px text. In the token build at `b9ffb76` that is `#f2a927` on `#fff9e8`, which is 1.91:1 by the WCAG formula, below the 4.5:1 minimum of WCAG 2.1 success criterion 1.4.3 for text this size. In the dark token values it is `#f8be4c` on `#654208`, 5.33:1. The ruling's "Not ruled" line names it, so it is not waived. Figma's Table frame draws no warning tag, so there is no design to compare it with. It is owned by the designer or the token owner, and changing the colour would touch other components.

From the [release review](https://github.com/mavismon/horizon-design-system/blob/6ecb1f053761687f66b1a01250a7318968790029/reports/Table/release-review.md), under "Warnings", as written:

> Warning tag contrast about 2:1. --color-status-warning text on --color-status-warning-bg (Table.css:138-141) is about 2:1 for 11px text, below WCAG AA. Named in the ruling's "Not ruled", so not waived. Figma's Table frame draws no warning or info tag. Owner: the designer or token owner. Changing the colour would touch other components.

**Not in Figma: the keyboard focus ring.** The ring ([`Table.css:188-193`](https://github.com/mavismon/horizon-design-system/blob/b9ffb76f7673fe33ddc04617d587557e93084f96/src/components/Table/Table.css#L188-L193): a `2px` `--color-border-focus` outline at a `2px` offset) was added by the engineer. The last fact above says it exists. Its contrast was not measured by the review, and the designer has not confirmed it.

**Dark theme: not verified.** Tokens do not switch under `prefers-color-scheme: dark`, so the dark values on the Code tab are what the token build declares, and the review did not verify them on a rendered table. The review calls this library-wide, not a Table finding.

## Design gaps recorded against it

**Warning tag colours: low contrast, and no Figma node for them.** Figma's Table frame draws no warning or info tag, so the warning pair `--color-status-warning` on `--color-status-warning-bg` ([`Table.css:138-141`](https://github.com/mavismon/horizon-design-system/blob/b9ffb76f7673fe33ddc04617d587557e93084f96/src/components/Table/Table.css#L138-L141)) has nothing to be checked against. The contrast problem is described on the Usage tab under Accessibility.

From the [release review](https://github.com/mavismon/horizon-design-system/blob/6ecb1f053761687f66b1a01250a7318968790029/reports/Table/release-review.md), under "Warnings", as written:

> Warning tag contrast about 2:1. --color-status-warning text on --color-status-warning-bg (Table.css:138-141) is about 2:1 for 11px text, below WCAG AA. Named in the ruling's "Not ruled", so not waived. Figma's Table frame draws no warning or info tag. Owner: the designer or token owner. Changing the colour would touch other components.

**Not in Figma, added by the engineer.** The descending sort arrow, the keyboard focus ring and the disabled Previous / Next are listed on the Usage tab. The designer still has to confirm them. The disabled rule ([`Table.css:182-186`](https://github.com/mavismon/horizon-design-system/blob/b9ffb76f7673fe33ddc04617d587557e93084f96/src/components/Table/Table.css#L182-L186)) sets a border colour, a text colour and a cursor and no background; `--color-state-disabled-bg` is used for the border colour only.

**Tag tones with no pixel spec.** Only success is drawn in the table. From the [release review](https://github.com/mavismon/horizon-design-system/blob/6ecb1f053761687f66b1a01250a7318968790029/reports/Table/release-review.md), under "Warnings", as written:

> Neutral, error, warning and info tag colours have no pixel spec in the Figma Table frame; QA passed them on geometry and token consistency.

**Dark theme.** From the [release review](https://github.com/mavismon/horizon-design-system/blob/6ecb1f053761687f66b1a01250a7318968790029/reports/Table/release-review.md), under "Warnings", as written:

> Dark theme unverified. Tokens do not switch under prefers-color-scheme: dark (QA note 5). Library-wide, not a Table finding.

**No story for the descending sort.** `Table.stories.tsx` has `SortedAscending` and no story that sets `direction: "descending"`; in Storybook the descending state is reached only by clicking the sort header in `Interactive`.

From the [release review](https://github.com/mavismon/horizon-design-system/blob/6ecb1f053761687f66b1a01250a7318968790029/reports/Table/release-review.md), under "Warnings", as written:

> No story for descending sort; reachable through Interactive. Owner: engineer, if wanted.
