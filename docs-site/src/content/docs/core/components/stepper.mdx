## When to use it

- Use type progress at the top of a flow with three to five steps, such as booking: Dates and guests, Your details, Extras, Payment, Confirm.
- Use type quantity to set a small number with − and +, such as Adults, Children and Rooms in the guests picker and filters.
- Use state at-min when the value is at its lowest (0 children, 1 adult) and at-max at its highest, so the button can't go further.

## When not to use it

- For a flow of one or two steps: a page title is enough.<br/>*The Figma page names no alternative.*
- For a number that can be large or exact, such as a price: use a text field.<br/>*The Figma page names no alternative.*
- To show how far something has loaded: use Progressbar.<br/>**Instead:** ProgressBar

## Best practice

From the Figma documentation page (usage node `216:84`), as written. These items aren't carried into `Stepper.intent.json`, which has no field for them.

- Keep step labels to one to three words, and let people go back to a done step by clicking it.
- Mark every step before the current one as done; never skip ahead past an upcoming step.
- Give each counter a clear label, and say the limits nearby when they aren't obvious, such as "Up to 8 guests".
