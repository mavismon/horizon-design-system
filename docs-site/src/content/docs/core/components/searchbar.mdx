## When to use it

- Use type field to search within one list or page, such as "Search messages", "Search reviews" or the back office "Search" in the header.
- Use size md (36px) on web and in the back office; use size lg (44px) in the mobile app for a bigger tap target.
- Use type stay at the top of the website and search results to find a stay by place, dates and guests.
- Say what is being searched in the placeholder: "Search messages", not just "Search", unless the page makes it obvious.
- Show the clear (×) button as soon as there is text, and keep the typed value after the results load.
- In type stay, always show a value in each part, such as the dates already chosen, never an empty slot.

## When not to use it

- To filter by fixed values such as status or property: use Chip filters or a Dropdown.<br/>**Instead:** Chip, Dropdown
- To type data into a form, such as a name or an address: use a text field.<br/>**Instead:** text field
- More than one type stay on the same page.<br/>*The Figma page names no alternative.*

## Variant matrix

`type` (2) × `size` (2) × `state` (3) = 12 combinations, of which Figma publishes 7 cells. The component set (213:54) publishes 7 variants, not the 12 that type x size x state would give: type field has all six size x state cells (md and lg, each empty, focused and filled); type stay has one, size lg, state filled (960 wide). Placeholder, Value and the stay values Where, Check in, Check out and Guests are properties of the set, not cells; the specimen board (214:7) draws them as the instances Back office (214:14), Trips (web) (214:19) and App, lg (214:24). ## Design gaps recorded against it

**The registry link is the canvas.** The Figma cell for SearchBar on the board holds the canvas page (node `57:1645`, `Searchbar`), not the component set (`213:54`). The page header's Figma link goes to that canvas and says so; the frame above is the documentation frame `214:7`.

From the [release review](https://github.com/mavismon/horizon-design-system/blob/6df21f0ef4120bfddede90c2e296da2d55e37249/reports/SearchBar/release-review.md), under "Findings outside the gates", as written:

> Registry link. The Figma cell holds the canvas page (node-id=57-1645), not the component set 213:54. Owner: the cell's owner.

**The icon size is an attribute, not a token.** The search icon and the clear icon each carry `width="14" height="14"` on the `<svg>` ([`SearchBar.tsx:48`](https://github.com/mavismon/horizon-design-system/blob/680282ead001fb5128702575d313303134d3261e/src/components/SearchBar/SearchBar.tsx#L48), [`SearchBar.tsx:56`](https://github.com/mavismon/horizon-design-system/blob/680282ead001fb5128702575d313303134d3261e/src/components/SearchBar/SearchBar.tsx#L56)), and `SearchBar.css` sets no width or height on `.hz-searchbar__icon`. From the [release review](https://github.com/mavismon/horizon-design-system/blob/6df21f0ef4120bfddede90c2e296da2d55e37249/reports/SearchBar/release-review.md), under "SVG icon attributes (width="14" height="14")", as written:

> SearchBar.tsx line 48 (search icon) and line 56 (clear icon) both carry width="14" height="14" viewBox="0 0 14 14" as attributes on the &lt;svg&gt;, not in the stylesheet.
>
> Does gate 2 cover them? My reading, unchanged from the first review: no. The gate's "how to answer" says "read every declaration in the component's stylesheet". Gate 2 as written covers stylesheets only. These are markup attributes with unitless numbers (SVG user units), and SearchBar.css has no width or height on .hz-searchbar__icon. The gate's one-line question could be read more widely. If a human intends it to reach markup attributes, these are a finding with no covering ruling (decisions.md has no SearchBar ruling; the Button ruling covers Button.css only). A ruling would have to name width="14" and height="14" on SearchBar.tsx:48 and :56, accepted because they are the Figma icon size and no icon size token exists (the spacing scale has 12 and 16px, not 14px). I did not write it. The Cleared verdict rests on the stylesheet-only reading; if the human reads gate 2 more widely, this verdict must be revisited.
