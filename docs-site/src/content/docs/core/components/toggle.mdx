## When to use it

- To turn a single setting on or off, such as a notification ("Check in reminders", "Price drop alerts").
- For a setting that takes effect immediately, without a Save button.
- Use size md in settings lists, with the label and helper text on the left and the toggle on the right; use size sm in dense tables, such as the Email, Push and SMS columns.
- Use a disabled state for a setting the user can't change, such as booking confirmations that are always sent.

**Where the built component differs.** Item 3 (`145:824`) above is copied from Figma as written, and assumes a label and helper text laid out beside the toggle. `Toggle.tsx` renders one element, the `<input type="checkbox" role="switch">` ([`Toggle.tsx:14-19`](https://github.com/mavismon/horizon-design-system/blob/af4bc0f980df25322b5dc4bcfdbd6cfcbea52968/src/components/Toggle/Toggle.tsx#L14-L19)), with no label or helper-text slot, and the Figma component description says "No built-in label: place the setting's label beside it." (node `144:20`).

## When not to use it

- For a choice submitted together with a form, such as agreeing to terms: use the Checkbox component instead.<br/>**Instead:** Checkbox
- When the user must choose one of several options: use the Radiocard component instead.<br/>**Instead:** Radiocard
- To trigger an action, such as saving or sending: use the Button component instead.<br/>**Instead:** Button

## Best practice

From the Figma documentation page (usage node `145:712`), as written. These items aren't carried into `Toggle.intent.json`, which has no field for them.

- Always pair the toggle with a visible label that names the setting, not its state ("Price drop alerts", not "On").
- Apply the change straight away; don't make the user press Save afterwards.
- Leave optional notifications and marketing off by default.
- Explain why a disabled toggle can't be changed in the helper text (for example, "Always on, cannot be changed").
- Make the whole row clickable, not only the switch.
- Give the toggle the switch role and its label for assistive technology (role="switch" with aria-checked).

**Where the built component differs.** Items 4 (`145:872`) and 5 (`145:878`) are copied from Figma as written. They describe helper text and a clickable whole row, which `Toggle.tsx` doesn't provide: it renders only the bare switch, one `<input>` ([`Toggle.tsx:14-19`](https://github.com/mavismon/horizon-design-system/blob/af4bc0f980df25322b5dc4bcfdbd6cfcbea52968/src/components/Toggle/Toggle.tsx#L14-L19)), with no helper-text slot and no row to click. The label goes beside it, as the Figma component description says (node `144:20`).

Item 6 (`145:884`) names `role="switch"` with `aria-checked`. `Toggle.tsx` sets the role on a native checkbox input ([`Toggle.tsx:16`](https://github.com/mavismon/horizon-design-system/blob/af4bc0f980df25322b5dc4bcfdbd6cfcbea52968/src/components/Toggle/Toggle.tsx#L16)) and never sets `aria-checked`. The control is a native &lt;input type="checkbox"&gt; with role="switch", so keyboard, focus and disabled behaviour are the browser's own, and the checked state maps natively to the switch state (no manual aria-checked).

From the [release review](https://github.com/mavismon/horizon-design-system/blob/fbc021d4556de78fa83d47542827c202da7c68d5/reports/Toggle/release-review.md), as written:

Toggle is the bare switch: no label, helper text or row, and Figma draws only the switch. Owner: the designer (draw the row or trim the lines); the engineer builds it if drawn.

## Accessibility

- The control is a native &lt;input type="checkbox"&gt; with role="switch", so keyboard, focus and disabled behaviour are the browser's own, and the checked state maps natively to the switch state (no manual aria-checked). [`src/components/Toggle/Toggle.tsx:16`](https://github.com/mavismon/horizon-design-system/blob/af4bc0f980df25322b5dc4bcfdbd6cfcbea52968/src/components/Toggle/Toggle.tsx#L16)
- There is no built-in label; callers supply aria-label or wrap the input in a &lt;label&gt; to give it an accessible name. [`src/components/Toggle/Toggle.stories.tsx:12`](https://github.com/mavismon/horizon-design-system/blob/af4bc0f980df25322b5dc4bcfdbd6cfcbea52968/src/components/Toggle/Toggle.stories.tsx#L12)

## Variant matrix

`size` (2) × `state` (4) = 8 cells. The documentation frame (145:2) lays out size (rows: md, sm) against state (columns: off, on, disabled-off, disabled-on). ## Design gaps recorded against it

- **2026-10-02 · Toggle track heights and disabled alpha with no token** ([decisions.md](https://github.com/mavismon/horizon-design-system/blob/af4bc0f980df25322b5dc4bcfdbd6cfcbea52968/decisions.md)). These literals in src/components/Toggle/Toggle.css are accepted, because they are what the Figma node specifies, until the designer adds matching size and opacity tokens. Accepted values: `24px` (height (md track), `the md switch track`, line 16); `22px` (height (sm track), `the sm switch track`, line 21); `40%` (alpha in color-mix(in srgb, var(--color-primary-default) 40%, transparent) (disabled-on track only), `the disabled and checked switch track`, line 45). *Not ruled:* Any other literal value, including a var() fallback. These values in any other component. A change to these values: a different number needs a new ruling or a token. The on track, which uses --color-primary-default (#2b5ad6) and differs from the #3b71f2 Figma shows: that is the user's choice to use the bound token, not a gate finding. The low contrast of the off track and of the knob on the disabled-off track as Figma draws them, which the user chose to build as drawn: that needs the designer. Any state Figma does not draw (hover, pressed, error, loading).
