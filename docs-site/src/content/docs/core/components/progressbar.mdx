## When to use it

- To show how full something is against a known total, such as a property's occupancy for a night ("38 of 48 · 79%").
- To compare parts of a whole side by side, such as revenue by booking channel, with each share as the Value.
- To show a score out of a maximum, such as review scores by category; hide the label row when the layout already names it.
- Use tone inverse on navy backgrounds, such as a sold-out night in the calendar.

**Not built.** The last "when to use" item (Figma node `140:204`) is copied from Figma as written, and it recommends something this build does not have. [`ProgressBarTone`](https://github.com/mavismon/horizon-design-system/blob/74d5360af63af3256916af73269892f68dcc95b5/src/components/ProgressBar/ProgressBar.tsx#L6) has only `primary`, `success`, `neutral`. From [decisions.md](https://github.com/mavismon/horizon-design-system/blob/74d5360af63af3256916af73269892f68dcc95b5/decisions.md), "2026-10-02 · ProgressBar inverse tone not built": Gate 5 passes for the missing inverse tone, and for that tone only, until the designer gives the inverse track a colour distinct from its fill and the tone is built. The user decided to build only the three working tones (primary, success, neutral). No story is drawn for the inverse tone, and the tone union does not include it.

## When not to use it

- For steps in a flow, such as "1 of 3": use the Stepper component instead.<br/>**Instead:** Stepper
- To compare exact figures across many rows: use the Table component instead.<br/>**Instead:** Table

## Best practice

From the Figma documentation page (usage node `140:82`), as written. These items aren't carried into `ProgressBar.intent.json`, which has no field for them.

- Always show the number too, as the Value or a nearby label; the bar alone isn't precise and screen readers can't read it.
- Pick the value (0 to 100 in steps of 10) and type the same number in Value, so the bar and the text agree.
- Keep bars in the same group the same size and width so they can be compared.
- Give colours a consistent meaning, such as one colour per booking channel, and name it in the label.
- Use size sm in dense layouts such as calendar cells, and md everywhere else.
- Keep the fill between 0 and 100%; show overbooking with a separate marker, not a bar longer than its track.

**Where the built component differs.** Item 2 (Figma node `140:232`) says to type the same number in Value. `ProgressBar.tsx` has no separate Value text to type: it prints the text from `value` itself. The Code tab says how.

## Accessibility

- The component renders a native &lt;progress&gt; with max=100, so the progressbar role and value announcement are the browser's own. [`src/components/ProgressBar/ProgressBar.tsx:59`](https://github.com/mavismon/horizon-design-system/blob/74d5360af63af3256916af73269892f68dcc95b5/src/components/ProgressBar/ProgressBar.tsx#L59)
- The visible label is linked to the &lt;progress&gt; with aria-labelledby, using an id generated by React's useId. [`src/components/ProgressBar/ProgressBar.tsx:63`](https://github.com/mavismon/horizon-design-system/blob/74d5360af63af3256916af73269892f68dcc95b5/src/components/ProgressBar/ProgressBar.tsx#L63)
- When showLabel is false the label text is applied as aria-label so the progress bar keeps an accessible name. [`src/components/ProgressBar/ProgressBar.tsx:64`](https://github.com/mavismon/horizon-design-system/blob/74d5360af63af3256916af73269892f68dcc95b5/src/components/ProgressBar/ProgressBar.tsx#L64)
- The helper text is linked with aria-describedby when it is shown. [`src/components/ProgressBar/ProgressBar.tsx:65`](https://github.com/mavismon/horizon-design-system/blob/74d5360af63af3256916af73269892f68dcc95b5/src/components/ProgressBar/ProgressBar.tsx#L65)
